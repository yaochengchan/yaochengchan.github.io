A low-cost robot head that let us test behavior before autonomy existed

An MVP hardware testbed that tested the riskiest assumption first: whether people read a robot head's movement as attention.

My role
Hardware and system prototyping, CAD, user pilots
Collaborators
Carnegie Mellon University (Howie Wang, Dr. Nikolas Martelaro)
Scope
MVP testbed for real-time remote control and behavior testing
Methods
Iterative prototyping, Wizard-of-Oz pilots
Tools
Autodesk Fusion, 3D printing, Python
Hardware
Raspberry Pi, Dynamixel servos

The problem

Autonomous gaze software would take a long time to build and debug, and user testing on how people read robot attention couldn't wait for it.

What I did

Co-built a two-axis puppeteering rig, so the robot head mirrors an operator's handheld controller in real time, and refined it over three hardware iterations.

The result

Test setup went from hours to minutes, and pilots showed that pan and tilt alone are enough to show where the robot is looking.

The problem

Robots moving through public spaces need clear gaze and direction cues to avoid collisions and earn trust. But building and debugging autonomous computer vision and gaze tracking on a mobile robot is slow and fragile, and it would have blocked user testing for a long time.

The riskiest assumption wasn't technical. It was about people: would they even read a robot head's movement as attention? We needed to answer that first, cheaply.

My role

I co-developed the testbed in collaboration with Howie Wang and Dr. Nikolas Martelaro at Carnegie Mellon University. I owned the hardware and system prototyping, the CAD design of the head across iterations, and the user pilots that evaluated each version.

The key decision: build a puppet, not a brain

Instead of waiting for autonomy software, we built a Wizard-of-Oz puppeteering rig. An operator moves a small handheld "puppet" and the robot head mirrors it in real time on two axes, pan and tilt. That let us create and test behaviors directly in front of participants.

Why it mattered: preparing a user test went from hours of software calibration to minutes, so the team could try more behaviors with more people, sooner.

Three iterations

  • Phase 1

    Proof of concept: a flat wooden plate

    To isolate motion from appearance, the first version was just a wooden plate on a pan-tilt base, with no eyes or face. Pilot finding: people still read the plate as the robot's "face" and correctly interpreted where it was attending from its angle and movement speed.

  • Phase 2

    CAD: custom enclosure & camera housing

    Modeled a head assembly in Autodesk Fusion with internal cable routing and two camera mounts, keeping it light enough for the Dynamixel servos. I balanced the servos' torque limits against gear backlash so subtle movements stayed fast and smooth.

  • Phase 3

    3D-printed binocular head

    The final version had two eye-like structures, inspired by animation design, that made the forward direction unmistakable. Validation: participants said the synchronized head tilts felt responsive and approachable and showed clearly where the robot was "looking."

How it works

Input

Operator puppet

A handheld two-axis rig built from Dynamixel AX-12W servos used as position sensors, read in real time over USB.

Compute

Two Raspberry Pis

Python scripts package joint positions into small timestamped messages and send them over a local network.

Output

Robot head

Mirrors the operator in real time. Optimized message sizes and idle sleep timers cut lag and save power.

Outcome

01

Two axes of motion are enough

Pan and tilt alone show where the robot is paying attention, so there was no need for an expensive multi-axis animatronic face in navigation settings.

02

Testing that wasn't blocked by software

A reliable rig made real-time human-in-the-loop studies possible both in the lab and on mobile robots outdoors.

03

Shape tells people where it's facing

Two eye-like forms helped pedestrians read the robot's direction much faster than a flat, featureless surface did.
